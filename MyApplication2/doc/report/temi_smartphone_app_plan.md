## 1. 문서 확인 요약

PPTX에는 Temi와 연동되는 스마트폰 앱의 주요 화면 흐름이 정의되어 있다. 핵심 기능은 수납 관리, 쇼핑리스트 생성/저장, 물품 DB 조회, Temi 및 서랍 장치 연결 설정이다.

PDF는 `AGI-Driven Temi Shopping` 제목의 Chrome 생성 PDF이며, 현재 환경에서는 텍스트 레이어 추출이 제한되어 세부 문구는 확인되지 않았다. 따라서 세부 화면/기능 계획은 PPTX의 화면 정의를 기준으로 작성하고, PDF는 AGI 기반 쇼핑/Temi 연동 방향성을 보강하는 참고 자료로 반영한다.

현재 Android 프로젝트는 Java 기반 기본 앱 상태이며, `MainActivity`와 `activity_main.xml`만 존재한다. 실제 기능 구현을 위해 화면 구조, 데이터 저장소, 카메라/QR/네트워크/Temi 연동 계층을 새로 설계해야 한다.

## 2. 앱 목표

사용자가 스마트폰 앱에서 물품 수납 상태를 등록하고, 여러 사용자의 쇼핑 요청을 통합해 구매 리스트를 만들며, 가정용 Temi와 매장 Temi에 필요한 정보를 전송할 수 있게 한다.

주요 목표:
- 카메라 촬영 또는 갤러리 이미지 기반으로 수납 물품 후보를 생성한다.
- 사용자가 물품과 서랍 위치를 확인/수정한 뒤 수납 절차를 진행한다.
- 여러 사용자의 구매 요청을 하나의 쇼핑리스트로 통합한다.
- 보유 물품과 구매 필요 물품을 분류하고 저장한다.
- 물품명, 개수, 위치를 조회할 수 있는 로컬 DB를 제공한다.
- QR 기반으로 가정용 Temi, 매장 Temi, 연동 서랍을 연결한다.
- 저장된 쇼핑리스트를 매장 Temi로 전송한다.

## 3. 주요 사용자 흐름

### 3.1 홈

홈 화면은 다음 네 가지 진입점을 제공한다.
- 수납추가
- 쇼핑리스트
- DB조회
- 설정

### 3.2 수납 흐름

1. 사용자가 `수납추가`를 선택한다.
2. 카메라 촬영 화면에서 실시간 미리보기, 촬영, 갤러리 선택, 분석을 수행한다.
3. 분석 결과로 탐색된 임시 수납 리스트를 보여준다.
4. 사용자는 음성추가 또는 수동추가로 항목을 보정한다.
5. 수납가이드 화면에서 지정된 순서대로 물품을 서랍에 넣는다.
6. 센서 상태, 진행률, 완료/미완료 상태를 확인한다.

### 3.3 쇼핑리스트 흐름

1. 사용자별 구매 희망 품목을 입력한다.
2. 하단 입력창에서 물품명과 개수를 추가한다.
3. 여러 사용자의 목록을 통합해 1차 구매 품목 리스트를 만든다.
4. 리스트 이름을 지정한다.
5. 보유/구매필요 상태를 분류한다.
6. 보유 항목은 전체 제외할 수 있고, 최종 리스트를 저장한다.

### 3.4 DB 조회 흐름

1. 물품명을 입력한다.
2. 검색 버튼을 누른다.
3. 같은 이름이라도 위치가 다르면 별도 항목으로 표시한다.
4. 리스트에는 물품명, 개수, 위치를 표시한다.

### 3.5 설정 및 장치 연결 흐름

설정 화면은 다음 메뉴로 구성한다.
- 가정 Temi
- 매장 Temi
- 서랍 관리

가정용 Temi 설정:
- 연결된 가정용 Temi 표시
- QR 카메라로 Temi 검색
- QR 인식 성공 시 연결 버튼 활성화

매장 Temi 설정:
- QR 기반 매장 Temi 연결
- 저장된 쇼핑리스트 선택 팝업
- 선택한 리스트를 매장 Temi로 전송

서랍 관리:
- QR 기반 서랍 연결
- 연결된 서랍 리스트 확인

## 5. 데이터 모델 초안

### 5.1 Item

물품 기본 정보.
- `id`: 고유 ID
- `name`: 물품명
- `quantity`: 개수
- `location`: 위치 또는 서랍 번호
- `drawerId`: 연결 서랍 ID
- `createdAt`
- `updatedAt`

### 5.2 StorageTask

수납 진행 단위.
- `id`
- `itemId`
- `targetDrawerId`
- `order`
- `status`: `PENDING`, `IN_PROGRESS`, `DONE`, `SKIPPED`
- `sensorVerified`: 센서 확인 여부

### 5.3 ShoppingList

저장된 쇼핑리스트.
- `id`
- `name`
- `createdAt`
- `updatedAt`
- `items`
- `status`: `DRAFT`, `SAVED`, `SENT`

### 5.4 ShoppingListItem

쇼핑리스트 항목.
- `id`
- `shoppingListId`
- `name`
- `quantity`
- `ownerName`
- `needToBuy`: 구매필요 여부
- `reason`: 품절, 보유, 위치불명 등 선택적 사유

### 5.5 TemiDevice

Temi 연결 정보.
- `id`
- `name`
- `type`: `HOME`, `STORE`
- `endpoint`
- `authToken`
- `lastConnectedAt`

### 5.6 DrawerDevice

연동 서랍 정보.
- `id`
- `name`
- `qrCode`
- `connectionStatus`
- `lastSensorStatus`

## 6. 기술 설계

현재 프로젝트가 Java + XML 기반이므로 1차 구현은 기존 구조를 유지한다. 화면 수가 많아지면 Activity 다중 구성보다 `MainActivity + Fragment + Navigation` 구조가 적합하다.

권장 구성:
- UI: XML Layout + Fragment
- 화면 이동: AndroidX Navigation Component
- 로컬 DB: Room
- 비동기 처리: Java Executor 또는 Kotlin 전환 시 Coroutine
- QR 인식: ML Kit Barcode Scanning 또는 ZXing
- 카메라: CameraX
- 이미지 선택: Android Photo Picker 또는 SAF
- 네트워크: Retrofit + OkHttp
- 로컬 설정: SharedPreferences 또는 DataStore

Temi 연동은 실제 SDK/프로토콜 확인 후 결정한다. 초기 단계에서는 `TemiRepository` 인터페이스를 만들고, 실제 연결 전에는 Mock 구현으로 화면과 데이터 흐름을 먼저 완성한다.

## 7. 권한 계획

필요 권한:
- `CAMERA`: 카메라 촬영 및 QR 인식
- `RECORD_AUDIO`: 음성추가 기능 사용 시
- `INTERNET`: Temi/서버/API 연동
- `ACCESS_NETWORK_STATE`: 네트워크 상태 확인
- Android 버전에 따른 이미지 접근 권한 또는 Photo Picker 사용

권한 요청은 기능 진입 시점에 수행한다. 예를 들어 카메라 화면 진입 시 `CAMERA`, 음성추가 버튼 선택 시 `RECORD_AUDIO`를 요청한다.

## 8. API 및 연동 계획

### 8.1 VLM/AGI 분석 API

카메라 또는 갤러리 이미지 분석에 사용한다.

입력:
- 이미지
- 분석 목적: 수납 물품 탐색, 물품명 추정, 개수 추정

출력:
- 물품명
- 개수
- 추천 위치 또는 서랍
- 신뢰도

초기 구현에서는 API 응답 Mock 데이터를 사용해 UI와 저장 흐름을 먼저 만든 뒤, 실제 API 키와 엔드포인트가 확정되면 연결한다.

### 8.2 Temi 전송 API

매장 Temi에 쇼핑리스트를 전송한다.

입력:
- Temi 식별자
- 쇼핑리스트 ID
- 구매필요 항목 목록

출력:
- 전송 성공/실패
- Temi 수신 상태
- 실패 사유

### 8.3 서랍 센서 API

수납가이드에서 카메라/로드셀 상태를 확인한다.

입력:
- 서랍 ID
- 현재 수납 대상 물품

출력:
- 센서 연결 상태
- 감지 여부
- 무게 변화 또는 상태값

- 로컬 저장소

중간:

- QR 연결 UI

낮음 또는 외부 의존:
- 실제 VLM 분석
- 실제 Temi 전송
- 실제 서랍 센서 연동
- 음성추가

외부 SDK와 장치 사양이 확정되지 않은 기능은 인터페이스와 Mock 구현을 먼저 만들고, 실제 연동부는 교체 가능하게 유지한다.

## 11. 리스크 및 확인 필요 사항

- Temi와 스마트폰 앱의 연결 방식이 확정되어야 한다. 예: Temi SDK, REST API, WebSocket, BLE, 로컬 네트워크 등.
- QR 코드에 담긴 데이터 형식이 필요하다. 예: 장치 ID, endpoint, auth token.
- 서랍 센서의 통신 방식과 데이터 포맷이 필요하다.
- VLM/AGI 분석 API의 입력 제한, 비용, 응답 형식, 개인정보 처리 정책 확인이 필요하다.
- Android 13 이상 이미지 권한 정책을 고려해야 한다.
- 오프라인 상태에서 저장과 전송 재시도를 어떻게 처리할지 결정해야 한다.
